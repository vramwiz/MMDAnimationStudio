# MMDポーズ学習

この文書は、MMDAIPreviewからMMD共通コアを直接利用して、AIが意図したポーズを組み立てるために、実機で確認した判断規則と注意事項を記録する。2026-08-27にAul2MIRAIからコピーし、以後のポーズ学習記録はこちらを正本とする。

MMDAIPreviewの要求形式は[`..\note.md`](../note.md)を正本とする。AIMIRAIに関する記述は、完成ポーズをAviUtl2へ適用する段階の参考として残す。本書ではAPI定義を重複させず、ポーズ設計と実機学習へ重点を置く。確定値の機械可読コピーは[`confirmed-poses.json`](confirmed-poses.json)に置く。

## 目的

- ボーン名や保存文字列をAI側で推測せず、対象MMDプラグインからモデル固有の骨格を取得する。
- 自然言語の「会釈」「ファイティングポーズ」などを、複数ボーンの移動・回転へ変換する。
- 適用前にMMD側で意味検証と最終位置計算を行い、未知ボーンや不正回転を拒否する。
- ポーズ適用後のレンダリングを確認し、意味的な成功と見た目の成功を区別して学習する。

## 記録規則

- 具体的なポーズ名、ボーン値、完成例は、ユーザーがそのポーズを確定した場合だけ本書へ記録する。
- 作成途中の姿勢、AIの自己評価、API上の適用成功だけを完成ポーズとして記録しない。
- ユーザーから修正指示が続いているポーズは未確定とし、作業中のAviUtl2状態だけに保持する。
- 未確定ポーズから判明した一般的なAPI挙動、軸方向、エラー、安全上の制限は、ポーズ例と分離した技術事項として記録してよい。
- 衣服・髪・物理演算メッシュの貫通は現在のポーズ学習対象外とする。骨格、関節、手足、頭・胴の向きを評価する。

## 責任分担

学習中の外部AIは`MMDAIPreview.exe`を使用し、AviUtl2の状態を変更しない。完成ポーズを編集プロジェクトへ適用するときだけNamed Pipe `Aul2MIRAI.v1`を使用する。

| 担当 | 責任 |
| --- | --- |
| 外部AI | 自然言語からポーズ意図を解釈し、対象ボーンと回転候補を組み立て、画像を評価する。 |
| MMDAIPreview | MMD共通コアへの直接要求、複数視点、診断色、手指拡大、画像保存を管理する。 |
| AI MIRAI | 完成後の選択対象、`state_token`、設定値書込み、適用後照合、Undoを管理する。 |
| MMDプロバイダー | PMX読込み、ボーン・IKスキーマ、ボーン名の照合、回転正規化、最終ボーン位置計算を担当する。 |

初版の拡張名は`mmd.pose`である。スキーマ取得には`query_object_extension`、ポーズ検証には`preview_object_extension_change`、適用には`apply_object_extension_change`を使う。

## 対象の特定

1. `get_selected_objects`で現在選択中の対象と最新の`state_token`を取得する。
2. MMDの`モデル表示`または`ポーズ`エフェクトを探し、その配列位置を`effect_index`として使う。
3. `モデル表示`では`標準姿勢データ`、`ポーズ`では`姿勢データ`が書込み対象になる。
4. `index`、`effect_index`、`state_token`は保存せず、操作直前に必ず再取得する。
5. 対象が未選択なら勝手に別オブジェクトを編集せず、必要に応じてフォーカス移動を先にプレビューする。

## モデルスキーマから得られる情報

`get_model_schema`は次の判断材料を返す。

- モデル名、モデルファイル、モデルパスのSHA-256識別値
- 全ボーンのindex、名前、親index、初期位置、変形階層、PMXフラグ
- 継承親、継承率、IKボーンかどうか
- IKターゲット、反復回数、角度上限、リンクボーン、リンクごとの角度制限

実機で使用した「ふらすこきりたん」は224ボーン、IK 4本だった。`センター`、`上半身`、`上半身2`、左右の肩・腕・ひじ・手首、足・ひざ、左右足IKなどを名前で解決できた。

モデルごとにボーン名、追加ボーン、ローカル軸、可動域が異なるため、別モデルへ過去のボーン一覧をそのまま流用しない。まずスキーマを取得し、必要な名前が存在することを確認する。

## ポーズ要求

`set_pose`の`payload.mode`は次の2種類である。

| mode | 用途 |
| --- | --- |
| `replace` | 現在姿勢を破棄し、指定したボーンだけから新しいポーズを作る。別のポーズへ切り替える場合の基本。 |
| `merge` | 現在姿勢を保ち、指定したボーンだけを置き換える。画像確認後の微調整に使う。 |

各ボーンは`name`と、必要に応じて`translation`、`rotation`または`rotation_euler_degrees`を持つ。回転はQuaternion `[x,y,z,w]`かEuler度数 `[x,y,z]`のどちらか一方だけを指定する。

```json
{
  "mode": "merge",
  "bones": [
    {
      "name": "上半身",
      "rotation_euler_degrees": [-13, 0, 0]
    }
  ]
}
```

プレビュー成功時は正規化済み`pose_data`と、指定ボーンのindex、移動、Quaternion、最終ワールド位置が`resolved_bones`へ返る。`pose_data`をAI側で手作業編集せず、MMDが返した値だけを書込み候補にする。

## 安全な操作順

1. 最新の選択対象と`state_token`を取得する。
2. 初回は`replace`でポーズ全体を組み立てる。
3. `preview_object_extension_change`を実行する。
4. `status=ok`、`will_change=true`、解決ボーン数、最終位置を確認する。
5. 同じ状態と内容で`apply_object_extension_change`を実行し、`apply: true`を付ける。
6. `applied=true`と、`verified`がプロバイダーの`pose_data`と一致することを確認する。
7. フレーム画像を取得し、意図、シルエット、関節、衣装の破綻を目視する。
8. 修正は`merge`で必要なボーンだけに限定し、再度プレビューして適用する。

存在しないボーンは`bone_not_found`、重複指定は`duplicate_bone`、不正ベクトルや不正Quaternionは対応する意味エラーとしてプレビュー時点で拒否される。実機でも未知ボーン`存在しないボーン`が`bone_not_found`になり、状態が変化しないことを確認した。

## 実モデルで確認した回転傾向

以下は「ふらすこきりたん」を正面から表示した実測結果である。PMXモデルやカメラ向きが変われば見え方も変わるため、普遍的な符号規則として扱わない。

### Z回転と腕の上下

- 左腕はZを正方向へ回すと上がる。
- 右腕はZを負方向へ回すと上がる。
- 両腕を下ろす場合は概ね左腕を負、右腕を正へ回す。
- ひじのZ回転を上腕へ加えると、手の高さと身体への寄り方が大きく変わる。

### Y回転と腕の奥行き

左右の腕は初期方向が反対なので、同じ「身体の前へ出す」操作でもY符号が反対になる。

- 左肩・左腕はYを正方向へ寄せると、このモデルの正面カメラでは手が身体の前へ出た。
- 右肩・右腕はYを負方向へ寄せると前へ出た。
- 左を負、右を正にした奥行き試験では、両手が身体の後ろへ隠れた。
- 符号を反転すると、両手が身体の前へ出た。

奥行きは正面画像だけでは判断しにくい。手が胴体や袖に隠れた場合、角度を大きくする前に左右別のY符号を疑う。

### X回転と前後傾

この実機条件では、上半身のXを負方向へ回すと前傾した。自然な前後傾は1ボーンだけを大きく回さず、下半身、上半身、上半身2、首、頭へ目的に応じて分配する。具体値はユーザーがポーズを確定した後だけ記録する。

### センターと脚

- `センター`の移動・回転は全身へ影響するため、構図調整と姿勢設計を混同しない。
- 足・ひざなどIKリンクへ明示回転を入れると、MMD側はそのIKチェーンをFKとして扱う。IKで足を接地させたいポーズでは、足・ひざの明示指定を必要最小限にする。
- 体重移動や踏み込みは正面シルエットだけで決めず、足首位置と接地を別角度でも確認する必要がある。

## ポーズ評価

- APIが要求を受理し、ボーンを解決し、書込み後照合に成功しても、その意味のポーズに見えるとは限らない。
- AIはコマンド成功をポーズ完成とみなさず、ユーザーの意味評価を優先する。
- 頭や手など一部分だけで判断せず、全身のシルエット、関節位置、視線、左右差、奥行きを確認する。
- 手を身体へ置くポーズでは、手先だけでなく肩―肘―手首の連なりを確認する。手を近づけるために肘が胴へめり込む場合、上腕を外へ開き、前腕で手を内側へ戻す。
- 確定前の画像や数値を再利用可能なポーズテンプレートとして残さない。

## レンダリング確認の注意

ポーズ設定値の書込み完了と、`get_current_frame_image`が参照する描画世代はまだ同期していない。

- 適用直後の画像でメッシュやマテリアルの一部だけが欠ける場合がある。
- 複数ボーンの調整直後には上半身と下半身の一部が欠けたフレームを実際に取得した。
- この場合はポーズ失敗と決めつけず、不完全画像を破棄して少し待ってから再取得する。
- 再取得した完全フレームと、適用応答の`verified`を合わせて判断する。
- 同じ欠け方が複数回続く場合は、単なる同期遅延ではなくモデル描画または姿勢破綻として調査する。

将来はポーズ適用後の描画世代番号または更新完了待ちを追加し、時間待ちに依存しない確認へ変更する。

## AI専用診断ビュー

通常画像だけでは衣服や髪に隠れる骨格、手の裏表、指の区別が難しいため、AI MIRAIからMMDモデル表示を一時的な診断色でキャプチャできる。

- `bones`はモデル本人基準の左を青、右を赤、中央を黄として骨格だけを表示する。
- `bone_overlay`は単色モデルと骨格を同時表示する。モデル表面に隠れる骨格は`bones`で補う。
- `silhouette`は材質色とテクスチャを除外し、全身輪郭を明色で表示する。
- `finger_id`は衣服を除外し、親指を赤、人差指を黄、中指を緑、薬指を青、小指を紫へ割り当てる。右手は同色の明度65%で左右を区別する。
- `body_only`は身体と手足を肌色で表示し、袖や衣服に隠れた関節位置を確認する。
- `normal`は同じ経路で通常表示を取得し、診断結果と完成時の見た目を比較する。

診断表示はプロジェクトへ保存せず、AI MIRAIが開始、画像取得、解除を一体処理する。実機では全6表示の取得、各回の解除成功、取得前後の`state_token`一致、解除後の通常画像が取得前とSHA-256一致することを確認した。

`body_only`と`finger_id`の身体材質抽出は材質名による推定である。モデルによって身体メッシュの一部が存在しない場合もあるため、診断画像だけで完成と判断しない。骨格と指の方向を診断画像で評価した後、通常表示の正面、3/4、側面で衣服の厚み、袖、髪、貫通を確認する。

## 保存形式と上限

- AviUtl2設定値APIの現在の上限は1項目16,384文字である。
- 現在姿勢または生成後`pose_data`が上限を超える全身・指・表情の大規模姿勢は扱えない。
- `merge`は現在姿勢を一度読んで正規化して再出力するため、空の`bones`でも保存文字列が変わり`will_change=true`になる場合がある。
- 空mergeを「何もしない適用」の試験に使わない。プレビューで`will_change`を確認し、意図しない正規化なら適用しない。
- 意味が同じでも保存文字列の並びや数値表現が変わる可能性があるため、適用前後の比較はMMDが返した正規化値と書込み後`verified`で行う。
